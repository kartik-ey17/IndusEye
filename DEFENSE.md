# SentinelAI — judge questions

## Why YOLO?

YOLO provides one-stage object detection with a clear bounding-box/confidence API and a mature local Python ecosystem. That makes it practical for live operator overlays and evidence crops.

## Why a lightweight model?

The demo must process camera frames on a laptop while also running face anonymization and a dashboard. YOLO11n trades some accuracy capacity for practical latency; YOLO11s is a straightforward upgrade where GPU headroom exists.

## Why fine-tune rather than use only pretrained detection?

COCO is broad but not surveillance-weapon-specific and has no dedicated gun class. Fine-tuning a three-class head on weapon-labelled imagery aligns labels and camera conditions with the task. This checkout is transparent that `models/best.pt` is absent, so the fallback is not presented as a completed gun detector.

## How do you handle low light?

The quality module measures brightness, blur, and noise. The preprocessing module conditionally uses gamma, CLAHE, mild denoise, and restrained sharpening. Low-light degradation is also included in the robustness harness.

## How did augmentation affect robustness?

The configured training plan varies illumination, scale, framing, mosaic, and occlusion; small train-only CCTV copies add blur/noise/compression without destroying every knife edge. Quantified effectiveness requires the fine-tuned weights and labelled test set; we do not claim it from the fallback run.

## How do you reduce false positives?

Use a centralized confidence threshold, person/weapon spatial association, a cooldown tracker, and operator review of face-blurred evidence. The output remains an indicator, not an automatic decision.

## Why blur faces?

It minimizes routine exposure of bystanders while preserving object-level safety context. The live dashboard never renders raw browser video.

## How do you stop duplicate alerts?

`IncidentProcessor` keeps an active incident for continuous weapon detections and resets it only after the configurable cooldown has elapsed without a weapon.

## How do you measure latency?

The integrated processor uses `time.perf_counter()` around preprocessing, detector inference, privacy, and the full pipeline. `evaluation/final_results.csv` is generated by execution, after model warm-up.

## Why FastAPI?

It gives concise typed HTTP endpoints, automatic API documentation, dependable local serving, and a clean boundary between React and the Python CV stack.

## How would this work with CCTV?

Point `SENTINEL_CAMERA_SOURCE` to a local capture/stream source or send JPEG frames to `/api/process-frame`. The CV pipeline and incident database remain unchanged.

## What are the limitations?

This checkout lacks locally available fine-tuned weights and labelled test data, so there are no valid mAP claims. CPU throughput is limited; small weapons, occlusion, motion blur, and unusual viewpoints remain difficult. Face detection can miss faces. The system requires human review.

## Does the AI determine that a crime occurred?

No. It reports visual incident indicators such as a weapon-like object; it does not determine legality, intent, or guilt.

## How would you scale this system?

Move inference to edge GPUs, use one worker per stream with bounded queues, add durable object storage/metadata, add camera health monitoring, and introduce authenticated operator/alert workflows only when product scope requires them.
